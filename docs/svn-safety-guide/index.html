Quick commands

The few commands you will type most. Each one links to the topic that explains it.

  • svn statusSee what you changedKnow where you are
  • svn diffRead your changes before committingReview your changes
  • svn infoCheck which branch you are onKnow where you are
  • svn updateGet other people's changesGet the latest
  • svn add fileStart tracking a new fileDo your work
  • svn commit -m "message"Share your work with the teamCommit your changes
  • svn switch "<address>"Move your folder to another branchSwitch branch

Stop and ask a developer if

  1. A C appears next to a scene, prefab, texture, model or any binary or data file. See Fix conflicts.
  2. You are about to run svn merge, or any command on a server address other than creating your own R&D branch. See Developer-only commands.
  3. svn status shows far more changes than you made. Don't commit.
  4. You committed something wrong, or to the wrong branch. See Undo and recover.
  5. A command or an error isn't in this guide. Ask before you run anything else.

How to read the steps

Required skipping it breaks something. Recommended skipping works, but you risk a mistake. Optional only when the reason under the step applies to you.

Read-only changes nothing. Local changes only files on your computer. Risky can lose work or cause conflicts. Shared everyone on the team sees it. Ask dev a developer should do this.

Daily path

Work through these in order, from checking where you are to sharing your work. Each topic says what comes before and after it.

1

Know where you are

Use this when: you start work, or before you run anything risky.

Before This is where you start.Next Get the latest
  1. svn infoRecommendedRead-only

    Shows the branch address, revision and last change of your folder. It answers "which branch am I on?" To print only the address, add --show-item url (SVN 1.9 or newer).

  2. svn statusRequiredRead-only

    Lists what you changed since your last update. It only reads your computer, so it is always safe.

  3. svn status -uOptionalRead-only

    Also marks files changed on the server since your last update, with a *. Use it when you want to know whether an update would bring changes. It contacts the server, so it needs your login.

What the letters in svn status mean
LetterMeaningWhat to do
MModified: you changed a tracked file.Normal. Read it in Review your changes before committing.
AAdded: marked to be added at your next commit.Normal.
DDeleted: marked for deletion at your next commit.Normal. svn revert undoes it before you commit.
?Not tracked: SVN doesn't know this file.Add it if it belongs in the project (Do your work), or remove it (Clean up).
!Missing: a tracked file was removed outside SVN, for example in Finder.svn revert file brings it back. See Undo and recover.
CConflict: you and someone else changed the same thing.Don't commit. See Fix conflicts.
XExternal: a file or folder the project pulls in from another location.Normal and not pending. Don't edit or delete it. A file external shows X in the fifth column.
IIgnored: SVN skips it on purpose. Only shown with --no-ignore.Normal.

The first column is about file contents. The second column is about properties (settings attached to a file or folder).

More options

See which folders define externals (read-only): svn propget svn:externals -R .

Changing externals is a developer job.

2

Get the latest

Use this when: you start your day, or before you commit, so you work from the newest files.

Before Know where you areNext Do your workIf something goes wrong Fix conflicts or Clean up
  1. Defocus UnityRecommended

    Unity doesn't need to be closed for an update. Just click away from it and stay in the terminal until the update finishes. Unity checks for changed files and refreshes .meta files when its window gets focus, which can interfere while SVN is writing files. When you go back to Unity, it imports the new files.

  2. svn statusRequiredRead-only

    Shows which edits are yours before anything changes. If a conflict appears later, you will know it came from a file you edited.

  3. svn updateRequiredLocal

    Downloads other people's changes and merges them into your files. Your own edits are kept. Wait until you see At revision N. and the prompt returns.

  4. Read what scrolls byRecommended

    The table below explains each letter. Most are normal.

  5. svn status | grep -E '^(C|.C|......C)'RecommendedRead-only

    Lists conflicts of every kind: in file contents, in properties, and tree conflicts. No output means no conflicts. If anything is listed, don't commit.

What the update output means
You seeMeaningWhat to do
UUpdated: the file now matches the server.Normal.
A / DA file was added or deleted to match the server.Normal.
GMerged: your edits and the server's were combined without trouble.Normal. Worth a look in Review your changes.
CConflict: your edits and the server's overlap.Don't commit. See Fix conflicts.
UUThe file's contents and properties were both updated. The first letter is for contents, the second for properties.Normal. It is not a conflict.
Fetching external itemThe project's externals are being refreshed.Normal.
At revision N.The update finished.Nothing. You are up to date.
Ask a developer if

You want an older revision (svn update -r N) or want every conflict settled by taking the server's version (--accept theirs-full, which discards your edits silently).

Errors here

Working copy locked or E155004: see Clean up. Unable to connect: check your VPN and Wi-Fi. Authorization failed: ask a developer.

3

Do your work

Use this when: you create, rename, move, delete or lock files. If you only edit existing files, you can skip this topic.

Before Get the latestNext Review your changesIf something goes wrong Clean up
  1. svn add fileOptionalLocal

    Only for new files you want to share. A new folder needs adding too, and adding a folder adds what is inside it. Undo with svn revert file before committing.

  2. svn move old newOptionalLocal

    Only when you rename or move a tracked file. It keeps the history. Moving a file in Finder makes SVN see one file deleted and another added. Move the asset and its .meta together, with Unity closed.

  3. svn delete fileOptionalLocal

    Only to remove a tracked file. Delete its .meta too. Undo with svn revert file before committing.

  4. svn lock fileOptionalShared

    Before editing a scene, prefab or large binary that someone else might also edit. A lock stops others from committing that file. Committing releases the lock for you.

  5. svn unlock fileOptionalShared

    Only to release your own lock without committing. Never use --force on someone else's lock.

Unity rules to follow while you work
  • Commit each .meta file together with its asset. Unity stores the asset's identity in it, and references break for everyone if it is missing or changes.
  • Never add generated folders: Library, Temp, Obj, Logs and usually UserSettings. If they show as ?, leave them and ask a developer to set up ignore rules.
  • Avoid svn add --force . at the project root. It adds every untracked file, including generated folders.
  • Don't change project-wide settings: Project Settings, packages, or the ProjectSettings folder.
Ask a developer if

You need to change ignore rules or other project settings, or delete, move or create folders directly on the server (commands that take a server address). Also for svn unlock --force.

4

Review your changes

Use this when: you are about to commit, or you want to see what changed.

Before Do your workNext Commit your changesIf something goes wrong Clean up or Undo and recover
  1. svn statusRequiredRead-only

    Check every line. M, A and D are your work. ? files need adding or removing. X lines are externals and are not pending.

  2. svn diffRecommendedRead-only

    Prints your uncommitted changes line by line. Add a file name to see one file. Binary files such as textures have no readable diff, so check them in svn status instead.

More options: filter the status list
CommandWhat it does
svn status -qLists only tracked files with changes and hides the ? files.
svn status | grep '^?'Lists only new files SVN doesn't track yet.
svn status | grep '^!'Lists only missing files.
svn status | grep -E '^(C|.C|......C)'Lists conflicts of every kind. No output means no conflicts.
svn status --ignore-externalsHides folder externals. File externals still show.
svn status | grep -vE '^.{4}X'Hides every X line, including file externals. If it prints nothing, nothing is pending.
svn status --no-ignore | grep '^I'Lists ignored files. A quick way to check that folders like Library are being ignored.
svn status <folder>Limits the list to one folder.
svn diff | lessShows a long diff one page at a time. Press q to quit.
Ask a developer if

svn status shows far more changes than you made. Don't commit. It is often generated folders such as Library or Temp, or the wrong folder.

5

Commit your changes

Use this when: your work is ready to share with the team.

Before Review your changesNext Prepare to switchIf something goes wrong Fix conflicts or Undo and recover
  1. svn statusRequiredRead-only

    Make sure the list holds only what you meant to change.

  2. svn add fileOptionalLocal

    Only if the list shows ? for new files you want to include. Remember their .meta files.

  3. svn diffRecommendedRead-only

    Read what you are about to publish.

  4. svn infoRecommendedRead-only

    The URL line shows the branch your commit will go to. It matters most when you use more than one folder or branch.

  5. svn commit -m "message"RequiredShared

    Sends your changes to the server as a new revision that everyone sees. It can't be erased, only reversed with a new commit, so write a short, clear message about what changed and why. Committing also releases your locks.

If the commit fails
  • ... is out of date: someone committed first. Get the latest, deal with any conflicts, then commit again.
  • Commit blocked by pre-commit hook: a server rule rejected it, for example the message format or a forbidden file. Read the message. If it is unclear, ask a developer.
  • ... is locked by user ...: another person holds a lock on that file. Message them. Don't force the lock.
  • Authorization failed or Access forbidden: ask a developer. Don't look for another login.
Ask a developer if

You committed something wrong, deleted a file and committed it, or committed to the wrong branch. Stop and see Undo and recover.

Branches

Moving your folder to another branch, and starting your own R&D branch. Switching only changes files on your computer, not the server.

6

Prepare to switch

Use this when: you are about to move your project folder to a different branch.

Before Commit your changesNext Switch branch
  1. Close UnityRequired

    A switch rewrites many files. Unity can regenerate files at the same time and cause conflicts.

  2. svn info --show-item wc-rootRecommendedRead-only

    Prints the top folder of your project. The last part of that path should match the folder name in your terminal prompt. Switching a subfolder gives you a mixed copy, so run the switch from the top folder (SVN 1.9 or newer).

  3. svn statusRequiredRead-only

    Make sure nothing in the list is work you would miss. Commit it first, or save it in the next step.

  4. svn diff > my-changes.patchOptionalLocal

    Only if you have edits you don't want to commit yet. It saves text edits to a file. New untracked files and binary files such as textures are not saved properly, so copy those by hand. Restore later with svn patch my-changes.patch.

Ask a developer if

You aren't sure which branch you need, or svn status shows a C.

7

Switch branch

Use this when: your project folder must point at a different branch.

Before Prepare to switchNext Switch back or recover or Get the latestIf something goes wrong Fix conflicts or Switch back or recover

Switch

  1. svn info --show-item urlRequiredRead-only

    Prints your current branch address, for example https://example.com/svn/project/branches/branch-a/MyProject. Write it down. It is your way back, and the new address is this one with only the branch name changed.

  2. svn ls "<branches-folder>"OptionalRead-only

    Only to see which branches exist. Skip it if you already know the exact name. The branches folder is the address up to and including /branches/.

  3. Build the new addressRequired

    Change only the branch name in your current address. Keep the start and the end exactly the same.
    From: https://example.com/svn/project/branches/branch-a/MyProject
    To: https://example.com/svn/project/branches/branch-b/MyProject
    A wrong address gives E195012 and changes nothing.

  4. svn switch "<new-address>"RequiredRisky

    Points your whole project folder at the new branch and downloads the differences. Wait until the prompt returns. Don't close the terminal or press Ctrl+C. If it is interrupted, see Switch back or recover.

Check the result

  1. svn status | grep -E '^(C|.C|......C)'RequiredRead-only

    No output means no conflicts. If anything is listed, don't commit. See Fix conflicts.

  2. svn infoRecommendedRead-only

    The URL line should show the new branch. Your next commit goes to this branch.

  3. Let Unity reimportRequired

    Open Unity and wait until it finishes. Then run svn status again before you commit anything.

What the switch output means
You seeMeaning
U, A, DFiles changed to match the new branch. Normal.
UUContents and properties both updated. Normal, not a conflict.
X lines and Fetching external itemThe project's externals. Normal.
CConflict. See Fix conflicts.
At revision N.The switch finished.
More options: finding branch names

Fill in the branches folder automatically from your current address (works only when it contains /branches/; if you are on trunk it lists the wrong folder, which is harmless, so use the manual way):

svn ls "$(svn info --show-item url | sed 's|/branches/.*|/branches/|')"

The branch list can be very long. Narrow it down:

CommandWhat it does
svn ls "<branches-folder>" | grep -i wordShows only branch names containing a word.
svn ls "<branches-folder>" | lessScroll the list one page at a time. Press q to quit.
svn ls -v "<branches-folder>" | sort -n | tail -20Shows the 20 most recently changed branches.
Ask a developer if

You want to use --ignore-ancestry, the switch reports conflicts, or you are unsure which branch to use.

Errors here

E195012, "does not share common version control ancestry" or "shares no common ancestry": the address is not the same kind of folder as your project folder, usually because part of the path is missing, such as the project folder at the end. Nothing was changed. Build the address again in step 3: start from the address in step 1 and change only the branch name. If it still fails, ask a developer. Never add --ignore-ancestry, because that turns the safety check off.

8

Switch back or recover

Use this when: you want to return to your previous branch, picked the wrong one, or a switch was interrupted.

Before Switch branchNext Get the latest or Do your workIf something goes wrong Fix conflicts
  1. Repeat the Prepare stepsRequired

    Close Unity and check svn status first. See Prepare to switch.

  2. svn switch "<previous-address>"RequiredRisky

    Use the address you wrote down in step 1 of Switch branch. This also fixes switching to the wrong branch, as long as you haven't committed on it.

  3. svn cleanupOptionalLocal

    Only if a switch was interrupted or SVN says the working copy is locked. Then repeat the same switch command.

  4. Check the resultRecommended

    Run the checks from Switch branch: the conflict check, svn info, and the Unity reimport.

Ask a developer if

You already committed on the wrong branch, or you switched only a subfolder and your folder is now mixed.

9

R&D branch: your own sandbox

Use this when: you want to experiment without touching what the team uses.

Before Agree the location and name with a developer.Next Do your work
Before you start

Ask a developer or lead which branch to copy from, where personal R&D branches live, what to name yours, and whether your account may create one. Rules differ between teams, and a wrong branch clutters the shared server. A large project also takes a while to check out the first time.

  1. svn info --show-item urlRequiredRead-only

    Prints the address of what you are copying. Check with the developer that it is the right source. On older SVN, run svn info and read the URL line.

  2. svn copy "<source-url>" "<your-branch-url>" -m "Create R&D branch: <short purpose>"RequiredShared

    Creates the branch on the server instantly and downloads nothing. Read both addresses twice before you press Enter, because everyone sees the new branch immediately. If SVN says the destination's parent folder doesn't exist, stop and ask a developer.

  3. svn ls "<your-branch-url>"RecommendedRead-only

    Should list the project's files, which confirms the branch exists.

  4. svn checkout "<your-branch-url>" project-rnd-yournameRequiredLocal

    Downloads the branch into a new, clearly named folder. Use a separate checkout, not svn switch, so your main work and your R&D stay apart.

  5. svn infoRequiredRead-only

    Run it inside the R&D folder before every commit and check that the URL line ends with your branch name. A commit goes wherever the folder points.

  6. Tell a developer when you are doneRequired

    They can review your work and merge the branch, or selected files, into the main line. Ask them to delete the branch when it is no longer needed.

Rules for R&D folders
  • Name the two folders clearly, for example project-main and project-rnd-yourname.
  • Don't run svn merge in either folder, and don't switch the R&D folder to another branch.
  • Don't copy files by hand between the two folders to move work across. It can silently overwrite someone's newer work.
  • Your branch slowly falls behind the main line. Updating it with newer main-line changes is a merge, so ask a developer. Short experiments rarely need it.
  • Commit to your branch as often as you like, but only what you need. Never commit generated folders.
Ask a developer for

The branch location and name, permission to create it, merging your work back, updating your branch from the main line, and deleting the branch when you are finished.

Side paths

Jump in from any step when something needs fixing, and use Back to where you were to return.

Fix conflicts

Use this when: any command shows a C, whether it came from an update, a switch or a commit that says "out of date".

A conflict happens when you and someone else changed the same file in overlapping ways. SVN won't guess, so it marks the file C and asks you to decide. Nothing is lost: both versions are kept next to your file.

  1. svn status | grep -E '^(C|.C|......C)'RequiredRead-only

    Lists every conflicted file. They also show C in the output of the command that caused them.

  2. StopRequired

    Don't commit. Don't delete the extra files SVN created next to the conflicted file (listed below).

  3. Check the file typeRequired

    If it is a scene, prefab, material, texture, model, PSD, data or config file, or any other binary or Unity asset, don't fix it by hand. Go to "Before you ask for help" below.

  4. Fix a plain text fileOptional

    Only for plain text such as notes or documentation, when the change is small and you understand both sides. Open the file and search for <<<<<<<. Keep the lines that are correct and delete the marker lines. Save the file.

  5. svn resolve --accept working fileRequiredLocal

    Tells SVN the conflict is fixed. Do it only after you have checked the file yourself. It also removes the extra files.

  6. svn diff fileRecommendedRead-only

    Check the result, then commit your changes.

<<<<<<< .mine
your version of the lines
=======
the server's version of the lines
>>>>>>> .r105

This is how a conflict looks inside a text file.

The extra files SVN creates
Extra fileWhat it holds
file.mineYour version of the file, as it was before the update.
file.rOLD (for example file.r100)The server version your edits were based on.
file.rNEW (for example file.r105)The latest server version.

Back to where you were

Before you ask for help
  • Copy the output of svn status and note the path of each conflicted file.
  • Copy file.mine to a safe place outside the project folder so your version can't be lost.
  • Note which branch you are on (the URL line from svn info).
  • Find out who made the other change with svn log -l 5 file. Agree together which version to keep. Only then keep one side with svn resolve --accept mine-full file or --accept theirs-full file. The second one discards your edits to that file.
Tree conflicts

A tree conflict happens when someone moved, renamed or deleted a file you edited. svn status shows an extra line starting with > under the file. Don't use any --accept shortcut. Ask a developer.

Clean up

Use this when: you see ? files you don't want, or SVN says the working copy is locked.

Two different jobs: removing files SVN doesn't track, and unlocking a folder SVN says is stuck.

A. Remove files SVN doesn't track

  1. svn status | grep '^?'RequiredRead-only

    Preview first. This list is exactly what the commands below would delete. Look for new assets or .meta files you haven't added yet, and for Library, Temp or Logs. If those are listed, SVN isn't ignoring them, so ask a developer before going further.

  2. Delete by hand in FinderRecommendedLocal

    Safest. Deleted files go to the Trash, so you can restore them.

  3. svn cleanup --remove-unversionedOptionalRisky

    Only to remove all untracked files at once. Permanent, with no Trash and no undo. Only your computer is affected, not the server. Needs SVN 1.9 or newer.

  4. svn cleanup --remove-unversioned <folder>OptionalRisky

    The same for one folder only. Preview it first with svn status <folder> | grep '^?'.

B. Unlock a stuck folder

  1. svn cleanupOptionalLocal

    Only when SVN says the working copy is locked (E155004), usually after a crash or an interrupted update. It repairs the folder and removes stale locks. Plain svn cleanup deletes nothing.

Back to where you were

Ask a developer if

You think about svn cleanup --remove-ignored. It also deletes ignored files such as Library and Temp, and Unity then needs a very long rebuild. Also ask if there are hundreds of ? files, or Library shows up in the list.

Files marked X

Those are externals, not untracked files. Cleanup doesn't touch them and svn revert can't clear them. Don't edit or delete them.

Undo and recover

Use this when: something went wrong with your local work or a commit.

Anything that has been committed stays in the repository history, so a developer can recover it. The only work that can be truly lost is uncommitted edits, which is why the risky commands need care.

SituationWhat to doRisk
I want to throw away my edits to one filesvn revert file

Permanent. If there is any doubt, save a copy first with svn diff file > backup.patch.

Risky
I want to throw away all my edits in this foldersvn revert -R .

Permanent. Read the svn status list first, because it is the only warning you get.

Risky
I want to save my edits before something riskysvn diff > my-changes.patch

Saves text edits to a file. Restore with svn patch my-changes.patch. New untracked files and binary files such as textures are not saved properly, so copy those by hand.

Local
I deleted a file in Finder and it shows !svn revert file

Brings back the last committed version. For a folder use svn revert -R folder.

Local
I forgot to add a file (or its .meta) before committingsvn add file

Then svn commit -m "Add missing file".

Local
I locked a file and forgot to unlock itsvn unlock file

If someone else holds a lock you need released, ask them or a developer.

Explore history and the server

Use this when: you want to see who changed what, or look around the server without changing anything.

All of these only read information. None of them changes your files or the server.

CommandWhat it does
svn logShows commit history: revision, author, date and message. Add -l N to limit it to N entries, -v to list the changed files, -r A:B to pick a revision range, --stop-on-copy to stop where the branch was created, and -q for a short list.
svn log -l 10Shows the last 10 commits.
svn log -l 10 -vThe same, with the files each commit changed.
svn log -l 5 fileShows the last 5 commits for one file.
svn log -r A:BShows a range of revisions.
svn log -v -r NShows what one revision changed.
svn log --search "word" -l 20Finds commits whose message or author contains a word, and limits the output to 20 entries. Needs SVN 1.8 or newer.
svn log --stop-on-copy -qLists the revisions on this branch only. The last one is where the branch was created.
svn diff -c NShows what revision N changed.
svn diff -r A:B fileCompares a file between two revisions.
svn diff --summarize -r A:B .Lists only the names of files that differ between two revisions, without the line changes.
svn blame fileShows each line of a text file with the revision and author who last changed it. Useful for finding who to ask about a change.
svn cat -r N filePrints a file as it was at revision N, without touching your copy.
svn info --show-item last-changed-author filePrints only who last changed a file. Needs SVN 1.9 or newer.
svn ls -v <url or path>Lists files and folders at a location, even on the server, with revision and author. No checkout needed.
svn list -RThe same, recursive. It can be very long on a big project, so pipe it into head or less.
svn export <url> folderDownloads a clean copy of a branch or folder with no .svn data. It writes to a new folder only.
svn proplist -vShows properties attached to files or folders, such as svn:ignore, svn:externals and svn:needs-lock. Viewing is safe. Changing them is for developers.
svn help <command>Prints the full options for any command.

Developer-only commands

Use this when: you wonder why a command isn't covered with steps here. These can affect other people's work or the whole project, and some can't be undone by you.

Command or situationWhy a developer should do it
svn merge (any form)It changes many files at once and can create conflicts that take hours to untangle. That includes bringing main-line changes into your R&D branch, and bringing your R&D work back.
svn switch with --ignore-ancestryThe option turns off the safety check against switching to an unrelated location.
svn update -r NIt moves your folder to an old revision. Editing or committing from there causes confusion.
svn update --accept theirs-fullIt silently throws away your edits in every conflicted file.
svn upgradeOne-way change. Older SVN tools may no longer open the folder afterwards.
svn cleanup --remove-ignoredIt also deletes ignored files such as Library and Temp, which forces a very long Unity rebuild.
svn delete, move, mkdir or copy on a server addressThese act on the shared server immediately and everyone sees them. The only exception is creating your own R&D branch.
svn propset, ignore rules, svn:externalsProject-wide settings. A wrong value affects everyone's checkout.
svn unlock --forceBreaks a lock held by someone else, who could lose work.
Reversing a commit, yours or someone else'sThe reversal becomes a new commit that everyone receives. A developer checks that nobody depends on it first.
Committing to the wrong branchFixing it needs reverse commits and merges. Stop and tell a developer.
Changing Unity project settings, packages or the ProjectSettings folderThese settings apply to everyone who opens the project.
"Authorization failed" or "forbidden"Your account may be missing access to that location. Don't look for another login.
Anything not in this guideLook it up with svn help <command> if you like, but ask before running it.

Glossary

Use this when: a word in this guide is new to you.

TermMeaning
RepositoryThe shared server copy of the project, with its full history.
Working copyThe folder on your computer that you edit. It is linked to the repository through a hidden .svn folder.
RevisionA numbered snapshot of the whole repository. Every commit creates the next number, for example r105.
HEADThe latest revision on the server.
BASEThe revision your folder was last updated to. svn diff compares your files against it.
CheckoutCreating a working copy by downloading a project from the repository for the first time.
CommitSending your local changes to the repository as a new revision.
UpdateDownloading other people's changes into your working copy.
TrunkThe main line of development. Most teams keep their stable or latest code here.
BranchA copy of the code on the server where work can happen separately from the main line.
R&D branchA branch you create for your own experiments, checked out into its own folder. See R&D branch.
SwitchPointing your existing project folder at a different branch. See Switch branch.
TagA named copy of the code at one moment, usually a release. It isn't meant to be changed.
MergeApplying the changes from one branch to another. A developer job in this guide.
ConflictTwo people changed the same file in overlapping ways, and SVN needs a person to choose what to keep.
LockA claim on a file that stops others from committing it until you release it.
PropertyA named setting attached to a file or folder, such as svn:ignore.
ExternalA file or folder the project pulls in automatically from another location. Shown as X in svn status. Changing externals is a developer job.
UnversionedA file SVN doesn't track yet. Shown as ? in svn status.
IgnoredA file SVN is told to skip, such as Library. Shown as I only with --no-ignore.
PatchA text file listing your edits, made with svn diff and re-applied with svn patch.
