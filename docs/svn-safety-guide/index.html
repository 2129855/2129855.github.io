Quick commands

The commands you'll type most. Each links to its topic.

  • svn statusSee what you changedKnow where you are
  • svn diffRead your changes before committingReview your changes
  • svn infoCheck which branch you are onKnow where you are
  • svn updateGet other people's changesGet the latest

  • svn commit -m "message"Share your work with the teamCommit your changes
  • svn switch "<address>"Move to another branchSwitch branch

Stop and ask a developer if

  1. A C appears next to a scene, prefab, texture, model, or any binary or data file. See Fix conflicts.
  2. You're about to run svn merge, or any command on a server address (except creating your own R&D branch). See Developer-only commands.
  3. svn status shows far more changes than you made. Don't commit.
  4. You committed something wrong, or to the wrong branch. See Undo and recover.
  5. A command or error isn't in this guide. Ask before running anything else.

How to read the steps

Required skipping it breaks something. Recommended skipping works but risks a mistake. Optional only if the note under the step applies to you.

Read-only changes nothing. Local changes only files on your computer. Risky can lose work or cause conflicts. Shared everyone on the team sees it. Ask dev a developer should do it.

Daily path

Do these in order, from checking where you are to sharing your work. Each topic links to what comes before and after.

1

Know where you are

Use this when: you start work, or before you run anything risky.

Before This is where you start.Next Get the latest
  1. svn infoRecommendedRead-only

    Shows your folder's branch address, revision and last change: answers "which branch am I on?" --show-item url prints only the address (SVN 1.9+).

  2. svn statusRequiredRead-only

    Lists what you changed since your last update. Reads only your computer, so always safe.

  3. svn status -uOptionalRead-only

    Also marks files changed on the server since your last update with *. Use it to see whether an update would bring changes. Contacts the server, so needs your login.

Status letters: what each one means
LetterMeaningWhat to do
MModified: you changed a tracked file.Normal. Check it in Review your changes before committing.
AAdded: will be added at your next commit.Normal.
DDeleted: will be deleted at your next commit.Normal. svn revert undoes it before you commit.
?Not tracked: SVN doesn't know this file.Add it if it belongs in the project (Do your work), or remove it (Clean up).
!Missing: a tracked file was removed outside SVN, e.g. in Finder.svn revert file brings it back (Undo and recover). Moved or renamed it? See Do your work.
CConflict: you and someone else changed the same thing.Don't commit. See Fix conflicts.
XExternal: a file or folder the project pulls in from elsewhere.Normal, not pending. Don't edit or delete it. A file external shows X in the fifth column.
IIgnored: SVN skips it on purpose. Shown only with --no-ignore.Normal.

The first column is about file contents, the second about properties (settings on a file or folder).

More options

See which folders define externals (read-only): svn propget svn:externals -R .

Changing externals is a developer job.

2

Get the latest

Use this when: you start your day or before you commit, to work from the newest files.

Before Know where you areNext Do your workIf something goes wrong Fix conflicts or Clean up
  1. Defocus UnityRecommended

    No need to close it. Click away and stay in the terminal until the update finishes. Unity refreshes assets and .meta files when it regains focus, which can interfere while SVN writes files. On return, it imports the new files.

  2. svn statusRequiredRead-only

    Shows which edits are yours, so a later conflict traces back to a file you edited.

  3. svn updateRequiredLocal

    Downloads others' changes and merges them into your files; your edits are kept. Wait for At revision N. and the prompt.

  4. Read what scrolls byRecommended

    The table below explains each letter. Most are normal.

  5. svn status | grep -E '^(C|.C|......C)'RecommendedRead-only

    Lists conflicts of every kind: contents, properties, and tree conflicts. No output means none. If anything is listed, don't commit.

Update output: what each line means
You seeMeaningWhat to do
UUpdated: the file now matches the server.Normal.
A / DA file was added or deleted to match the server.Normal.
GMerged: your edits and the server's combined cleanly.Normal. Worth a look in Review your changes.
CConflict: your edits and the server's overlap.Don't commit. See Fix conflicts.
UUContents and properties both updated (first letter contents, second properties).Normal, not a conflict.
Fetching external itemThe project's externals are refreshing.Normal.
At revision N.The update finished.Nothing. You're up to date.
This can take a while

On a very large project, an update plus the Unity import can take many minutes. A running command isn't frozen: wait for the prompt, don't interrupt. If interrupted, see Clean up.

Ask a developer if

You want an older revision (svn update -r N) or to settle every conflict by taking the server's version (--accept theirs-full, which silently discards your edits).

Errors here

Working copy locked or E155004: see Clean up. Unable to connect: check VPN and Wi-Fi. Authorization failed: ask a developer.

3

Do your work

Use this when: you create, rename, move, delete or lock files. If you only edit existing files, skip this topic.

Before Get the latestNext Review your changesIf something goes wrong Clean up
  1. svn add fileOptionalLocal

    Only for new files you want to share. Add a new folder too; adding a folder adds its contents. Undo with svn revert file before committing.

  2. svn move old newOptionalLocal

    Only to rename or move a tracked file; keeps history. A Finder move looks like a delete plus an add. Move the asset and its .meta together, Unity closed.

  3. svn delete fileOptionalLocal

    Only to remove a tracked file. Delete its .meta too. Undo with svn revert file before committing.

  4. svn lock fileOptionalShared

    Before editing a scene, prefab or large binary someone else might edit. Stops others committing that file; committing releases it.

  5. svn unlock fileOptionalShared

    Only to release your own lock without committing. Never use --force on someone else's lock.

  6. svn info "$(svn info --show-item url file)"OptionalRead-only

    Only when a file is read-only or a commit says it's locked. Find the Lock Owner line and message that person; don't force the lock. svn status -u file also shows O in the sixth column for someone else's lock. Needs SVN 1.9+.

If you renamed or moved assets in Unity or Finder

SVN doesn't notice renames: it sees the old path as missing and the new one as untracked, and the same for each .meta. svn status shows:

!       Assets/Old/icon.png
!       Assets/Old/icon.png.meta
?       Assets/New/icon.png
?       Assets/New/icon.png.meta

Easiest: SmartSVN. Select the missing and new files (with their .meta files), choose Modify | Detect Moves, and keep the pairs that match; history is kept. For one file, select exactly two (missing and new) and use Modify | Move. Menu names are from SmartSVN's docs and may vary by version.

Or use commands, either way below. The asset and its .meta travel together, so references keep working. Commit the deletion and addition in one commit, so nobody gets half the change.

Quick way: the file's history starts again

  1. svn delete "<old-path>" "<old-path>.meta"OptionalLocal

    Marks the old asset and .meta for deletion; works even though the files are gone.

  2. svn add "<new-path>" "<new-path>.meta"OptionalLocal

    Starts tracking the new asset and .meta.

  3. svn commit -m "message"RequiredShared

    Commits the deletion and addition together.

Keep the history: move it with SVN

  1. Put the asset and its .meta back in their old placeOptional

    Use Finder, with Unity closed. SVN can record a move only if the old file exists again.

  2. svn move "<old-path>" "<new-path>"OptionalLocal

    Moves the asset, keeping history.

  3. svn move "<old-path>.meta" "<new-path>.meta"OptionalLocal

    Same for the .meta. Then commit both together, as above.

Renamed many assets or whole folders, or references broke? Ask a developer.

Unity rules
  • Commit each .meta with its asset: it holds the asset's identity, and references break for everyone if it's missing or changes.
  • Never add generated folders: Library, Temp, Obj, Logs, usually UserSettings. If they show as ?, leave them and ask a developer for ignore rules.
  • Avoid svn add --force . at the project root: it adds every untracked file, including generated folders.
  • Don't change project-wide settings: Project Settings, packages, or the ProjectSettings folder.
Ask a developer if

You need to change ignore rules or other project settings, or delete, move or create folders directly on the server (commands that take a server address), or use svn unlock --force.

4

Review your changes

Use this when: you are about to commit, or you want to see what changed.

Before Do your workNext Commit your changesIf something goes wrong Clean up or Undo and recover
  1. svn statusRequiredRead-only

    Check every line. M, A, D are your work. ? files need adding or removing. X lines are externals, not pending.

  2. svn diffRecommendedRead-only

    Prints your uncommitted changes line by line; add a file name for one file. Binary files such as textures have no readable diff; check them in svn status.

More options: filter the status list
CommandWhat it does
svn status -qLists only tracked files with changes; hides ? files.
svn status | grep '^?'Lists only new files SVN doesn't track.
svn status | grep '^!'Lists only missing files.
svn status | grep -E '^(C|.C|......C)'Lists conflicts of every kind. No output means none.
svn status --ignore-externalsHides folder externals. File externals still show.
svn status | grep -vE '^.{4}X'Hides every X line, including file externals. No output means nothing is pending.
svn status --no-ignore | grep '^I'Lists ignored files: a quick check that folders like Library are ignored.
svn status <folder>Limits the list to one folder.
svn diff | lessShows a long diff one page at a time. Press q to quit.
In SmartSVN

Query | Show Changes shows the changes in each file side by side.

Ask a developer if

svn status shows far more changes than you made. Don't commit. Often it's generated folders such as Library or Temp, or the wrong folder.

5

Commit your changes

Use this when: your work is ready to share with the team.

Before Review your changesNext Prepare to switchIf something goes wrong Fix conflicts or Undo and recover
  1. svn statusRequiredRead-only

    Make sure the list holds only what you meant to change.

  2. svn add fileOptionalLocal

    Only if the list shows ? for new files you want to include. Remember their .meta files.

  3. svn diffRecommendedRead-only

    Read what you're about to publish.

  4. svn infoRecommendedRead-only

    The URL line shows the branch your commit goes to. Matters most with more than one folder or branch.

  5. svn commit -m "message"RequiredShared

    Sends your changes to the server as a new revision everyone sees. Can't be erased, only reversed by a new commit, so write a short, clear message: what changed and why. Also releases your locks.

Writing a commit message

Say what changed and why, in one line. "Update" or "fix" alone tells the next person nothing.

  • Update HUD icons for the winter event
  • Fix pivot on the garage door prefab
  • Add textures for the new track
In SmartSVN

Its commit window suggests files to add or remove and can detect renames.

Before a long break

Stopping for the day or longer? Commit finished work. Save unfinished text edits with svn diff > my-changes.patch; copy unfinished binary files such as textures by hand (a patch doesn't hold them). Nothing should live only on your computer.

If the commit fails
  • ... is out of date: someone committed first. Get the latest, deal with any conflicts, commit again.
  • Commit blocked by pre-commit hook: a server rule rejected it, e.g. message format or a forbidden file. Read the message; if unclear, ask a developer.
  • ... is locked by user ...: someone else holds a lock on that file. Message them; don't force the lock.
  • Authorization failed or Access forbidden: ask a developer. Don't look for another login.
Ask a developer if

You committed something wrong, deleted a file and committed it, or committed to the wrong branch. Stop; see Undo and recover.

Branches

Moving your folder to another branch, and starting your own R&D branch. Switching changes files on your computer only, not the server. Keep more than one copy of the project so you can switch branches quickly while a long feature stays untouched in the other copy (see R&D branch).

6

Prepare to switch

Use this when: you are about to move your project folder to a different branch.

Before Commit your changesNext Switch branch
  1. Close Unity, or at least defocus itRequired

    Closing is best. If it stays open, you must at least click away and stay in the terminal until the switch finishes: Unity refreshes assets and .meta files when it regains focus, and a switch rewrites many files, which can cause conflicts.

  2. svn info --show-item wc-rootRecommendedRead-only

    Prints the project's top folder; its last part should match your terminal prompt's folder name. Switch from the top folder: switching a subfolder gives a mixed copy. With several copies, it also confirms you're in the right one (SVN 1.9+).

  3. svn statusRequiredRead-only

    Make sure nothing listed is work you'd miss. Commit it first, or save it in the next step.

  4. svn diff > my-changes.patchOptionalLocal

    Only for edits you don't want to commit yet. Saves text edits to a file; new untracked files and binary files such as textures aren't saved properly, so copy those by hand. Restore with svn patch my-changes.patch.

Which copy am I in?

With more than one copy, check before every switch: the folder name in your terminal prompt and the URL line from svn info. Switching in the wrong copy is the easiest mistake.

Ask a developer if

You're unsure which branch you need, or svn status shows a C.

7

Switch branch

Use this when: your project folder must point at a different branch.

Before Prepare to switchNext Switch back or recover or Get the latestIf something goes wrong Fix conflicts or Switch back or recover

Switch

  1. svn info --show-item urlRequiredRead-only

    Prints your current branch address, e.g. https://example.com/svn/project/branches/branch-a/MyProject. Write it down: it's your way back, and the new address is this one with only the branch name changed.

  2. svn ls "<branches-folder>"OptionalRead-only

    Only to see which branches exist; skip it if you know the exact name. The branches folder is the address up to and including /branches/. SmartSVN's Repository Browser shows them too.

  3. Build the new addressRequired

    Change only the branch name in your current address; keep the start and end identical.
    From: https://example.com/svn/project/branches/branch-a/MyProject
    To: https://example.com/svn/project/branches/branch-b/MyProject
    A wrong address gives E195012 and changes nothing.

  4. svn switch "<new-address>"RequiredRisky

    Points the whole folder at the new branch and downloads only the differences. Wait for the prompt; don't close the terminal or press Ctrl+C. If interrupted, see Switch back or recover.

Check the result

  1. svn status | grep -E '^(C|.C|......C)'RequiredRead-only

    No output means no conflicts. If anything is listed, don't commit. See Fix conflicts.

  2. svn infoRecommendedRead-only

    The URL line should show the new branch; your next commit goes there.

  3. Let Unity reimportRequired

    Open Unity and wait until it finishes, then run svn status again before committing anything.

Switch output: what each line means
You seeMeaning
U, A, DFiles changed to match the new branch. Normal.
UUContents and properties both updated. Normal, not a conflict.
X lines and Fetching external itemThe project's externals. Normal.
CConflict. See Fix conflicts.
At revision N.The switch finished.
More options: finding branch names

Fill in the branches folder from your current address (works only if it contains /branches/; on trunk it lists the wrong folder, which is harmless, so use the manual way):

svn ls "$(svn info --show-item url | sed 's|/branches/.*|/branches/|')"

The branch list can be very long. Narrow it:

CommandWhat it does
svn ls "<branches-folder>" | grep -i wordShows only branch names containing a word.
svn ls "<branches-folder>" | lessScroll the list one page at a time. Press q to quit.
svn ls -v "<branches-folder>" | sort -n | tail -20Shows the 20 most recently changed branches.
This can take a while

On a very large project, a switch plus the Unity reimport can take many minutes. A running command isn't frozen: wait for the prompt, don't interrupt. If interrupted, see Switch back or recover.

Ask a developer if

You want --ignore-ancestry, the switch reports conflicts, or you're unsure which branch to use.

Errors here

E195012, "does not share common version control ancestry" or "shares no common ancestry": the address isn't the same kind of folder as your project folder, usually because part of the path (e.g. the project folder at the end) is missing. Nothing changed. Rebuild it in step 3 from the address in step 1, changing only the branch name. Still failing? Ask a developer. Never add --ignore-ancestry: it turns the safety check off.

Switch back or recover

Use this when: you want to return to your previous branch, picked the wrong one, or a switch was interrupted.

Before Switch branchNext Get the latest or Do your workIf something goes wrong Fix conflicts
  1. Repeat the Prepare stepsRequired

    Close or defocus Unity and check svn status first. See Prepare to switch.

  2. svn switch "<previous-address>"RequiredRisky

    Use the address you wrote down in step 1 of Switch branch. Also fixes switching to the wrong branch, if you haven't committed on it.

  3. svn cleanupOptionalLocal

    Only if a switch was interrupted or SVN says the working copy is locked. Then repeat the same switch command.

  4. Check the resultRecommended

    Run the checks from Switch branch: conflict check, svn info, Unity reimport.

Ask a developer if

You already committed on the wrong branch, or switched only a subfolder and your folder is now mixed.

9

R&D branch: your own sandbox

Use this when: you want to experiment without touching what the team uses.

Before Agree the location and name with a developer.Next Do your work
Keep more than one copy of the project

Two or three copies work well. Mid-feature, another copy lets you jump to a branch for R&D or a quick task without disturbing the feature. Each copy stays on its own branch, and switching one onto a new branch is quick.

Before you start

Ask a developer or lead: which branch to copy from, where personal R&D branches live, what to name yours, and whether your account may create one. Rules differ by team, and a wrong branch clutters the shared server.

  1. svn info --show-item urlRequiredRead-only

    Prints the address of what you're copying; confirm with the developer it's the right source. On older SVN, run svn info and read the URL line.

  2. svn copy "<source-url>" "<your-branch-url>" -m "Create R&D branch: <short purpose>"RequiredShared

    Creates the branch on the server instantly; downloads nothing. Read both addresses twice before Enter: everyone sees the new branch immediately. If SVN says the destination's parent folder doesn't exist, stop and ask a developer.

  3. svn ls "<your-branch-url>"RecommendedRead-only

    Should list the project's files, confirming the branch exists.

  4. Prepare your R&D copyRequired

    Open your R&D copy, not your main one. Close or defocus Unity and check svn status, as in Prepare to switch.

  5. svn switch "<your-branch-url>"RequiredRisky

    Moves that copy onto your new branch (only the differences download). Then run the Switch branch checks: conflict check, svn info, Unity reimport. Write down the previous address of that copy so you can switch back.

  6. svn infoRequiredRead-only

    Run it in the R&D copy before every commit; the URL line must end with your branch name. A commit goes wherever the copy points.

  7. Tell a developer when you are doneRequired

    They can review your work and merge the branch, or selected files, into the main line. Ask them to delete the branch when it's no longer needed.

  8. svn switch "<previous-address>"OptionalRisky

    When the R&D is finished, switch the R&D copy back to a normal branch using the address you wrote down; it's then ready for your next experiment. Do the Prepare steps first.

Rules for your copies
  • Name copies clearly (e.g. project-main, project-rnd) and check svn info before committing in any.
  • Don't run svn merge in any copy.
  • Don't copy files by hand between copies to move work; it can silently overwrite newer work.
  • Your branch slowly falls behind the main line; updating it is a merge, so ask a developer. Short experiments rarely need it.
  • Commit to your branch as often as you like, but only what you need; never generated folders.
Ask a developer for

The branch location and name, permission to create it, merging your work back, updating your branch from the main line, and deleting the branch when you're done.

Side paths

Jump in from any step when something needs fixing, then use Back to where you were to return.

Fix conflicts

Use this when: any command shows a C, whether from an update, a switch, or a commit that says "out of date".

You and someone else changed the same file in overlapping ways. SVN won't guess: it marks the file C and asks you to decide. Nothing is lost; both versions are kept next to your file.

  1. svn status | grep -E '^(C|.C|......C)'RequiredRead-only

    Lists every conflicted file. They also show C in the output of the command that caused them.

  2. StopRequired

    Don't commit. Don't delete the extra files SVN created next to the conflicted file (listed below).

  3. Check the file typeRequired

    A scene, prefab, material, texture, model, PSD, data or config file, or any other binary or Unity asset: don't fix it by hand. Go to "Before you ask for help" below.

  4. Fix a plain text fileOptional

    Only for plain text such as notes or documentation, when the change is small and you understand both sides. Open the file, search for <<<<<<<, keep the correct lines, delete the marker lines, save.

  5. svn resolve --accept working fileRequiredLocal

    Tells SVN the conflict is fixed. Only after you've checked the file yourself. Also removes the extra files.

  6. svn diff fileRecommendedRead-only

    Check the result, then commit your changes.

What a conflict looks like
<<<<<<< .mine
your version of the lines
=======
the server's version of the lines
>>>>>>> .r105

How a conflict looks inside a text file.

SVN also creates three extra files next to the conflicted one:

Extra fileWhat it holds
file.mineYour version of the file, as it was before the update.
file.rOLD (e.g. file.r100)The server version your edits were based on.
file.rNEW (e.g. file.r105)The latest server version.

Back to where you were

In SmartSVN

The Conflict Solver shows both versions side by side (a three-way merge), easier than editing markers by hand. Scenes, prefabs and binary files still go to a developer.

Before you ask for help
  • Copy the output of svn status and note each conflicted file's path.
  • Copy file.mine outside the project folder, so your version can't be lost.
  • Note your branch (the URL line from svn info).
  • Find out who made the other change with svn log -l 5 file. Agree which version to keep. Only then keep one side with svn resolve --accept mine-full file or --accept theirs-full file; the second discards your edits to that file.
Tree conflicts

Someone moved, renamed or deleted a file you edited. svn status shows an extra line starting with > under the file. Don't use any --accept shortcut; ask a developer.

Clean up

Use this when: you see ? files you don't want, or SVN says the working copy is locked.

Two jobs: removing files SVN doesn't track, and unlocking a folder SVN says is stuck.

A. Remove files SVN doesn't track

  1. svn status | grep '^?'RequiredRead-only

    Preview first: this list is exactly what the commands below delete. Check for new assets or .meta files you haven't added yet, and for Library, Temp or Logs; if those are listed, SVN isn't ignoring them, so ask a developer first.

  2. Delete by hand in FinderRecommendedLocal

    Safest: deleted files go to the Trash, so you can restore them.

  3. svn cleanup --remove-unversionedOptionalRisky

    Removes all untracked files at once. Permanent: no Trash, no undo. Your computer only, not the server. Needs SVN 1.9+.

  4. svn cleanup --remove-unversioned <folder>OptionalRisky

    The same for one folder only. Preview first with svn status <folder> | grep '^?'.

B. Unlock a stuck folder

  1. svn cleanupOptionalLocal

    Only when SVN says the working copy is locked (E155004), usually after a crash or interrupted update. Repairs the folder and removes stale locks. Plain svn cleanup deletes nothing.

Back to where you were

Ask a developer if

You're considering svn cleanup --remove-ignored (it also deletes ignored files such as Library and Temp, forcing a very long Unity rebuild), there are hundreds of ? files, or Library shows in the list.

Files marked X

Those are externals, not untracked files. Cleanup doesn't touch them and svn revert can't clear them. Don't edit or delete them.

Undo and recover

Use this when: something went wrong with your local work or a commit.

Committed work stays in the repository history, so a developer can recover it. Only uncommitted edits can be truly lost, which is why the risky commands need care.

I want to throw away my edits to one filesvn revert file

Permanent. If in doubt, save a copy first with svn diff file > backup.patch.

Risky
I want to throw away all my edits in this foldersvn revert -R .

Permanent. Read the svn status list first: it's the only warning you get.

Risky
I want to save my edits before something riskysvn diff > my-changes.patch

Saves text edits to a file; restore with svn patch my-changes.patch. New untracked files and binary files such as textures aren't saved properly; copy those by hand.

I deleted a file in Finder and it shows !svn revert file

Brings back the last committed version. For a folder use svn revert -R folder. Renamed or moved it instead? See Do your work.

Then svn commit -m "Add missing file".

Explore history and the server

Use this when: you want to see who changed what, or look around the server without changing anything.

All of these only read information; none changes your files or the server.

CommandWhat it does
svn logShows commit history: revision, author, date and message. Add -l N to limit to N entries, -v to list changed files, -r A:B for a revision range, --stop-on-copy to stop where the branch was created, -q for a short list.
svn log -l 10Shows the last 10 commits.
svn log -l 10 -vSame, with the files each commit changed.
svn log -l 5 fileShows the last 5 commits for one file.
svn log -r A:BShows a range of revisions.
svn log -v -r NShows what one revision changed.
svn log --search "word" -l 20Finds commits whose message or author contains a word; limits output to 20 entries. Needs SVN 1.8+.
svn log --stop-on-copy -qLists only this branch's revisions; the last is where the branch was created.
svn diff -c NShows what revision N changed.
svn diff -r A:B fileCompares a file between two revisions.
svn diff --summarize -r A:B .Lists only the names of files that differ between two revisions, not the line changes.
svn blame fileShows each line of a text file with the revision and author who last changed it. Useful for finding who to ask about a change. In SmartSVN: Query | Annotate.
svn cat -r N filePrints a file as it was at revision N, without touching your copy.
svn info --show-item last-changed-author filePrints only who last changed a file. Needs SVN 1.9+.
svn ls -v <url or path>Lists files and folders at a location, even on the server, with revision and author. No checkout needed.
svn list -RThe same, recursively. Can be very long on a big project: pipe it into head or less.
svn export <url> folderDownloads a clean copy of a branch or folder with no .svn data. Writes to a new folder only.
svn proplist -vShows properties attached to files or folders, such as svn:ignore, svn:externals and svn:needs-lock. Viewing is safe; changing them is for developers.
svn help <command>Prints the full options for any command.

Developer-only commands

Use this when: a command isn't covered with steps here. These can affect others' work or the whole project, and some can't be undone by you.

Command or situationWhy a developer should do it
svn merge (any form)Changes many files at once and can create conflicts that take hours to untangle. Includes bringing main-line changes into your R&D branch, and your R&D work back.
svn switch with --ignore-ancestryTurns off the safety check against switching to an unrelated location.
svn update -r NMoves your folder to an old revision; editing or committing from there causes confusion.
svn update --accept theirs-fullSilently throws away your edits in every conflicted file.
svn upgradeOne-way change; older SVN tools may no longer open the folder.
svn cleanup --remove-ignoredAlso deletes ignored files such as Library and Temp, forcing a very long Unity rebuild.
svn delete, move, mkdir or copy on a server addressAct on the shared server immediately; everyone sees them. Only exception: creating your own R&D branch.
svn propset, ignore rules, svn:externalsProject-wide settings; a wrong value affects everyone's checkout.
svn unlock --forceBreaks a lock held by someone else, who could lose work.
Reversing a commit, yours or someone else'sThe reversal is a new commit everyone receives; a developer checks nobody depends on it first.
Committing to the wrong branchFixing it needs reverse commits and merges. Stop and tell a developer.
Changing Unity project settings, packages or the ProjectSettings folderThese settings apply to everyone who opens the project.
"Authorization failed" or "forbidden"Your account may lack access to that location. Don't look for another login.
Anything not in this guideLook it up with svn help <command> if you like, but ask before running it.

Glossary

Use this when: a word in this guide is new to you.

TermMeaning
RepositoryThe shared server copy of the project, with its full history.
Working copyThe folder on your computer that you edit, linked to the repository through a hidden .svn folder.
RevisionA numbered snapshot of the whole repository; every commit creates the next number, e.g. r105.
HEADThe latest revision on the server.
BASEThe revision your folder was last updated to; svn diff compares your files against it.
CheckoutCreating a working copy by downloading a project from the repository for the first time.
CommitSending your local changes to the repository as a new revision.
UpdateDownloading other people's changes into your working copy.
TrunkThe main line of development; most teams keep stable or latest code here.
BranchA copy of the code on the server where work can happen apart from the main line.
R&D branchA branch for your own experiments, usually worked on in a spare copy of the project. See R&D branch.
SwitchPointing your existing project folder at a different branch. See Switch branch.
TagA named copy of the code at one moment, usually a release; not meant to change.
MergeApplying changes from one branch to another. A developer job in this guide.
ConflictTwo people changed the same file in overlapping ways; SVN needs a person to choose what to keep.
LockA claim on a file that stops others from committing it until you release it.
PropertyA named setting attached to a file or folder, such as svn:ignore.
ExternalA file or folder the project pulls in automatically from elsewhere. Shown as X in svn status. Changing externals is a developer job.
UnversionedA file SVN doesn't track yet. Shown as ? in svn status.
IgnoredA file SVN is told to skip, such as Library. Shown as I only with --no-ignore.
PatchA text file listing your edits, made with svn diff and re-applied with svn patch.
