SVN Terminal Commands - Safety Guide

Commands sorted by how much damage they can do. Run them from inside the project folder, for example /Users/hasingh/_SVN/_Claude/CSR2_CL/RacerUnity.

Tier 1: Read-only (always safe)

These don't change your files or the repository.

CommandWhat it does
svn statusCompares your files to the last update and lists what you changed. First-column letters: M modified, A added, D deleted, ? not under version control, ! missing, C conflict. Reads local data only.
svn status -uSame list, plus a column marking files changed on the server since your last update. Contacts the server, so it needs your login.
svn infoShows which repository URL, branch and revision your working copy is on, and who last changed it. Answers "which branch am I on?"
svn logShows commit history: revision, author, date and message. -l N limits to N entries, -v lists changed files, -r A:B selects a revision range, --stop-on-copy stops where the branch was created, -q gives a short list.
svn diffPrints your uncommitted changes line by line. Add a file name to see one file. -r A:B compares two revisions, -c N shows what revision N changed.
svn blame fileShows each line of a file with the revision and author who last changed it.
svn cat -r N filePrints a file as it was at revision N, without touching your copy.
svn ls <url or path>Lists files and folders at a location, even on the server, without checking anything out. -v adds revision and author.
svn list -RSame as ls, recursive. Can be very long on a big project, so pipe it into head or less.
svn proplist -v / propgetShows properties attached to files or folders, such as svn:ignore, svn:externals and svn:needs-lock.
svn mergeinfoShows what has been merged between branches. --show-revs eligible lists revisions available to merge, merged lists those already merged.
svn help <command>Prints full options for any command.

Tier 2: Local changes, easy to undo

Nothing reaches the server. You can reverse these before committing.

CommandWhat it does
svn add fileStarts tracking a new file. Nothing goes to the server until you commit. Undo with svn revert file.
svn delete fileMarks a tracked file for deletion and removes it locally. The server learns about it at commit. Undo with svn revert file before committing.
svn move old newRenames or moves a file and keeps its history. Prefer it over moving the file in Finder, which makes SVN see one file deleted and another added.
svn updateDownloads other people's changes and merges them into your files. If you edited the same lines as someone else you get a conflict (C). Run svn status first.
svn export <url> folderDownloads a clean copy of a branch or folder with no .svn metadata. Writes to a new folder only, so it's harmless.
svn cleanupRepairs a working copy after a crash or interrupted update and removes stale locks. Fixes "working copy locked" errors.
svn resolve --accept working fileTells SVN you've fixed a conflict so it stops flagging it. It doesn't choose the right content for you, so make sure the file is correct first.

Tier 3: Risky, can lose local work

Check svn status before running any of these.

CommandWhat it does and why it's risky
svn revert fileThrows away your uncommitted edits and restores the last committed version. Permanent. Nothing is saved anywhere, so you can't get your edits back.
svn revert -R .The same for every changed file in the current folder and below. Read the svn status list first.
svn merge <url>Applies changes from another branch to your working copy. Touches many files and may create conflicts. Nothing reaches the server until you commit, but fixing a bad merge can take hours. Preview with svn merge --dry-run <url>.
svn merge -c N <url>Merges only revision N, often to pull a single fix into your branch.
svn switch <url>Points your working copy at a different branch and downloads the differences. Conflicts are possible if you have local edits.
svn update --accept theirs-fullResolves every conflict by taking the server's version and discarding yours, with no warning per file.
svn upgradeConverts your working copy to the newest format. One-way: older SVN clients or SmartSVN versions may no longer open it.

Tier 4: Changes the shared server

Visible to everyone on the team.

CommandWhat it does and why it's risky
svn commit -m "message"Sends your changes to the server as a new revision everyone sees. It can't be erased, only undone with a new reverse commit. Run svn status and svn diff first and write a clear message.
svn copy <url> <url> -m "msg"Creates a branch or tag directly on the server. Cheap in SVN, but it creates a revision immediately and clutters the repository if the name is wrong.
svn delete <url> -m "msg"Deletes a file or folder on the server immediately, with no local step. Recoverable from history, but visible to everyone and may break builds.
svn move <url> <url>Renames or moves on the server immediately.
svn mkdir <url>Creates a folder on the server immediately.
svn lock filePrevents others from committing that file until you unlock it. Common for Unity scenes and binary assets. Release it when you're done.
svn unlock --force fileBreaks a lock held by someone else, which could cause them to lose work.
svn propset then commitChanges shared settings such as svn:ignore and svn:externals. A wrong value can affect everyone's checkout.

Habits that prevent most mistakes

  1. Run svn status before any command in Tier 3 or 4.
  2. Preview merges with --dry-run.
  3. Run svn diff before commit and read what you're about to publish.
  4. Before svn revert -R ., read the svn status list, because it's the only warning you get.
  5. If something looks wrong, stop and ask. Nothing in Tier 1 or 2 can hurt.
